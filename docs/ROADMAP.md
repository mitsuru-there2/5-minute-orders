# ロードマップ

作業区分・成果物・進行判定の提案は[開発計画](DEVELOPMENT_PLAN.md)を参照。
仕様・クリエイティブ・マニュアル・実装・試遊を、小さなプレイ版ごとに反復する。

1. **M0 開発基盤（実装済み）**: 原案保存、Godot起動、レイヤー分離、SPEC、固定版セットアップ、テスト、CI。
2. **M1 ルール検証**: マップ・国家・指揮官・命令モデル、衝突・勝利条件を決定。決定的な同時解決と観測情報生成をテストする。
3. **M2 プレイ可能版**: マップ、指揮官カード、命令確認、戦記ログ、観測情報のみを使うAI。ローカルDBの方式を選定し保存・再開を実装。外部サーバーなしで4陣営・4派閥・地形効果を含む1試合が完了する。
4. **M3 スマホ検証**: 日本語フォント、セーフエリア、タップ領域、通信を無効にした状態でのローカルDB保存・復帰、実機で入力時間と読み合いを評価する。
5. **M4 拡張判断**: 面白さの評価を受けて4派閥の拡張、指揮官能力・加入を設計。将来のオンラインマルチプレイに向けて費用・運用・権威サーバーの構成を判断する。

## 保留事項

- ローカルDB製品とGodot連携方式（保存機能の実装前にモバイル対応を検証して選定）。

- アプリ識別子、Apple Team ID、ストアアカウント、配布用署名。
- 初回実機検証で優先するOS・対象端末と最低対応OS。
- 上限ターン数とその時点の判定、人間脱落後の観戦・再戦、戦闘と退却、経済・補給の粒度。
  8×8固定・渡河中心で海軍なし・首都を失った国だけ脱落する方針は採用済み。
  脱落国の軍除去・残存領土中立化・占領済み領土保持・残存1国勝利・全国家同時脱落引き分けも採用済み。
- 外部公開ライセンス、ゲーム素材の権利表記。
- 指揮官の種類・具体的な加入条件・能力・毎ターンの命令（[SPEC 004](specs/004-commanders.md)）。
  通常上限5人・1派閥のみ6人、満員時の追加加入には解雇が必要。
  レア加入は毎ターンのランダム抽選、通常加入は中立部隊撃破で指揮官のみ加入を採用。
  能力・中立軍・抽選確率・解雇の詳細は未決定。
- 領土開発命令・最大3段階の発展を採用。[SPEC 005](specs/005-territory-development.md)で
  地形別の資金・資源・防衛補正の3軸、費用、占領時の扱い、兵力0からの補充を検討中。
  地形別の相対配分、資金を募集・補充／資材を開発に使う用途分担、領地ごとの単一発展Lvを採用。
  得意地形で開発速度2倍となる指揮官能力の方針を採用。具体的処理は検討中。
- 首都固定・指導者移動不可・毎ターンの指導者アクションを採用。
  人気と科学力、徴税・研究・人気向上の導入を採用。補正対象・数値・命令数は検討中。
  [SPEC 006](specs/006-factions-leaders.md)で4派閥の改訂案・指導者命令・指揮官枠との関係を検討する。

現在はM1-Aの仕様検討中。[M1 SPEC案](specs/002-m1-rules.md)に候補と判断待ち事項を記録する。
保留のゲームルールをSPECで具体化してからコードを追加する。人数・派閥数・地形範囲等の採用変更は[SPEC 003](specs/003-release-map-factions.md)を参照。詳細ルールは検討中・未実装。

兵種・徴兵方法・指揮官不在の守備隊は[SPEC 007](specs/007-units-recruitment-garrisons.md)で検討中。
指揮官がいなくても各自領で直接守備兵を徴兵できる方針を採用。
購入即時確定・新兵の当ターン利用を採用。指揮官のレベルアップと軍団上限最大10ユニットを採用。
最大Lv5・各Lvの枠配分と経験値、歩兵・弓兵・騎兵、
購入を命令枠から外すこと、守備隊上限・欠員補充の詳細は提案。
