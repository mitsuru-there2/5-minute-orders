# 販促戦略：SNS・SEOとX・Threads運用

作成日: 2026-09-09

状態: 広告費をかけず、SNSとSEOで販促する方針を記録した戦略案。
確定方針: Xはoyamonの技術・開発発信にゲーム開発を加え、Threadsはゲーム開発専用で運用する。
交流方針: 同じストラテジーゲームを楽しむ仲間として、共感・あるある・小さな質問を使い分ける。
対象層、投稿頻度、数値目標は検証用の仮案であり、成果の予測ではない。
本書の保存は、アカウントの変更、投稿、サイト公開、登録窓口の開設、紹介依頼の実施を意味しない。

## 1. 目的と前提

「SNS上で読み合いを体験する → 公式サイトで興味を深める → 試遊する」を中心に、
発売時の購入・ダウンロードにつながる関係を育てる。SEOは投稿や解説を後から発見してもらうために育成する。

- 広告出稿は行わない。まず日本語圏を対象とし、XとThreadsで役割を分けて運用する。
- 現在は開発基盤の段階。ゲームプレイ、AI、保存は未実装なので、初期目標は遊びたい人を見つけること。
- 初期版はオフライン・AI戦を予定。オンライン対人戦を実装済みの魅力として宣伝しない。
- 「5分」は命令入力を短時間に収める設計目標。「1試合5分」や強制タイマーを約束しない。
- 販促のために初期プロトタイプの範囲を広げない。ゲームの仕様は[プロトタイプSPEC](specs/001-prototype.md)に従う。
- 販促用の任意登録やWeb計測を、ゲームのプレイ・保存・再開の条件にしない。
- 広告費ゼロと、配布・ドメイン等を含む総費用ゼロは別。サービスや費用は採用時に確認する。

## 2. 届けたい相手と訴求

最初に検証する対象層:

- 戦略ゲームが好きだが、長時間の操作や終盤の管理が負担になっている人。
- ボードゲームの心理戦や、相手の意図を読む遊びが好きな人。
- 派手な映像より、地図と戦況から作戦を考えることが好きな人。

訴求の中心は「敵の動きを予想し、結果を見て驚く」体験。

> 操作は軽い。判断は重い。
> 敵は北に来る。それとも陽動か。
> 少数の指揮官に命令し、攻めと守りを読み合う『5分戦記』開発中。

- 現在の開発段階、初期版の範囲、よくある質問。

## 4. X：発見からフォローにつなげる運用

既存のoyamon（@oyamon_dev）を継続し、AI・コーディング・受託開発・Next/Vercelと
ゲーム開発を混ぜて発信する。「開発者が自分の戦略ゲームも作っている」という一貫性を保つ。
Xのゲーム専用アカウントは現時点で追加しない。
インプレッション獲得、フォロー獲得、ゲームへの関心を分けて評価する。

### プロフィール・紹介投稿

名前と既存の専門性・仕事の問い合わせ導線を維持し、プロフィールには
「個人で戦略ゲーム『5分戦記』開発中」を加える案とする。
ゲームの紹介投稿には特徴、地図または短い動画、開発段階、試遊情報へのリンクをまとめる。
固定投稿をゲーム紹介にするかは、仕事の導線とのバランスを見て判断する。

### 投稿の柱

| 型 | 例 | 狙い |
| --- | --- | --- |
| 作戦を選ぶ | 北に敵影。王都を守るか、迎撃するか | 参加・返信 |
| 結果に驚く | 北へ進軍したが、敵の狙いは南だった | 共有・次回への関心 |
| ゲーム好きの悩みに触れる | 領土が増えるほど命令が面倒になる問題 | 共感・プロフィール訪問 |
| 開発の進展 | 敵がいると思って進軍したら、もぬけの殻だった | 体験の理解・試遊への期待 |

開発報告は処理名より、プレイヤーに起きる体験で伝える。

投稿例（実装前は「企画検証用の架空の戦況」と明記）:

> 【あなたなら、どこを守る？】
> 北で敵軍を確認。しかし主力かどうかは不明。
> こちらの軍は1つ。
> A：北へ向かう
> B：王都を守る
> どちらを選ぶ？ 理由も聞きたい。

結果投稿では敵の命令と結果を公開し、何を予想して選び、どう当たった・外れたかを説明する。
不完全情報の判断を、結果だけから唯一の正解・不正解にしない。

### 見せ方

- 投稿単体で状況が分かるようにし、冒頭で判断したくなる問いを出す。
- 地図はスマホで読める文字サイズにし、地名・部隊・ルールを詰め込みすぎない。
- 動画は冒頭から戦況や決断を見せる。実装後は実プレイ素材に置き換える。
- 結果投稿にも元の状況を再掲する。
- 今回だけでも楽しめて、次回にも期待できる内容にする。結果公開をフォローの条件にしない。
- 好評な形式は別の配置・選択肢で続編にする。同じ文章の大量再投稿はしない。

### 週間投稿の仮案

既存の技術投稿を続け、ゲーム関連を週2本程度加える。

| 投稿 | 内容 |
| --- | --- |
| 制作・設計の実体験 | AIを使った実装、命令量を抑える設計、試行錯誤 |
| 遊び手向けの体験 | 地図と選択肢、敵の命令と結果、読み合い |

戦況を出した場合は結果も伝える。頻度に収めるため、同じ投稿の追記・返信や
翌週の投稿で補うなど調整する。ゲーム投稿だけに置き換えない。

### 初期の交流

1日10分程度を上限の目安に、戦略ゲーム・ボードゲームのプレイ感想を発信する人と会話する。
自分の投稿への返信では作戦を選んだ理由を聞き、別の見方も返す。
ゲーム開発者とは制作・操作性・見せ方について、ゲーマーとは好きなゲームや読み合いについて話す。
「実装がすごい」と「遊びたい」を別の反応として捉える。

関連する会話への返信例:

> 終盤は前線より、後方部隊の移動指示に時間がかかりますよね。
> どの操作が一番負担に感じますか？

相手の話題に沿って交流し、毎回宣伝リンクを付けない。
フォロー交換、定型文の大量返信、相互いいねの組織化は行わない。
投稿・返信・DM・紹介依頼の実行は、本書の保存とは別の作業とする。

### 共感・あるあるを軸にした返信（X・Threads共通）

採用方針: 「同じゲームに時間を溶かした仲間」として会話する。
ゲーム制作の紹介はプロフィールを基本とし、返信では相手の投稿の内容を優先する。

ユーザーがやり込んだと述べているゲーム:

- Dominions 5
- Stellaris（ステラリス）
- Hearts of Iron IV
- バトル・オブ・ポリトピア
- Europa Universalis IV
- Endless Legend

これらの経験を共通の話題として使う。ただし、特定の国家・陣営・MOD・プレイ時間・
勝敗など、ユーザーが述べていない具体的な体験を作って本人の経験として投稿しない。

| 返信の型 | 使う場面 | 例 |
| --- | --- | --- |
| 短い共感 | 感情や体験だけで十分伝わる | 勝ったのに、疲労感だけは敗戦国なんですよね。 |
| 共感＋あるある | プレイ経験と重なる状況 | あと1ターンでやめるつもりが、終わらせたい案件が毎ターン増えるんですよね。 |
| 共感＋小さな質問 | 相手の選択や続きが気になる | 内政に集中したい時ほど隣国が元気になりますよね。今回は迎撃しました？ 外交で粘りました？ |

短い共感を半分、あるあるを添える返信を残りの中心、質問は時々という配分を仮案とする。
毎回オチや質問を付けず、相手の温度感に合わせる。

#### 状況に合わせた返信の素材

以下は発想の見本。定型文として連投せず、実際の投稿に合う場合だけ調整して使う。

| 相手の状況 | 返信例 |
| --- | --- |
| 気づいたら深夜 | ゲーム内の国家より、現実の生活が崩壊しかけてますね。 |
| 拡張後の管理が大変 | 領土を増やすまでは征服者、増やしてからは事務職なんですよね。 |
| 複数戦線で戦争 | 一つ片付いたと思ったら、別の国境が光り始めるやつですね。 |
| 平和な内政の予定が戦争に | 平和に発展する予定だったんです。隣国が予定を読んでくれなかっただけで。 |
| 負けたのに再挑戦したい | 勝った回より、負けた回の「あそこでこうしてれば」が長く残りますよね。 |
| 開発で機能を増やしすぎた | プレイヤーには選択肢を増やしたいけど、開発者の退路が減っていくんですよね。 |

笑いの対象はゲームの状況や自分の欲張りさに置き、相手の腕前や失敗をからかわない。
落ち込んでいる投稿には冗談より素直な共感を選ぶ。
作品固有のルール、アップデートやMODに依存する話は確認してから触れる。
詳しさを競うより「同じ楽しさと苦労を知っている」と感じてもらう会話を目指す。

#### 返信先と進め方

- プレイ中の迷い、予想外の展開、敗戦の振り返り。
- 独自の戦略や縛りプレイの紹介。
- 個人開発者の操作性・ルール・バランス調整の悩み。
- フォロワー数にかかわらず、投稿者が返信に反応し、会話が続いている投稿。

ゲーム関連の交流は両媒体合計で1日10分、返信1〜3件を上限の目安とする。
件数はノルマにせず、既存の販促工数枠に含める。毎日実施して枠を超えるなら日数を減らす。

1. フォロー中の投稿と、好きなゲームの話題を見る。
2. 実際に共感した投稿にLIKEする。
3. 自分ならではの一言がある時だけ返信する。
4. 返事が来たら、その話題を続ける。

返信前に「この人の投稿だから書ける一文が入っているか」を確認する。
同じ人の全投稿に返信せず、無理に会話を引き延ばさない。
宣伝リンクは制作物を尋ねられた時など、話題に直接合う場合に使う。
この方針の文書化は、新たな投稿・返信・LIKEの実行や自動運用を開始する指示とは扱わない。

#### 交流の評価

週の振り返りでは、返信のいいね数に加えて次を確認する。

- 同じ相手と自然に再び話せたか。
- 相手から話しかけてもらえたか。
- プロフィールやゲームへの関心、試遊希望につながったか。

交流件数やフォローバック率だけを成功指標にしない。

### 4週間の比較検証

- 日本語圏向けに昼休みと夜を試す。特定の時間が必ず伸びるとは仮定しない。
- 「画像＋選択肢」と「画像＋投票」を比較する。
- 問いから始める形式と、意外な結果から始める形式を比較する。
- 少数の投稿で条件を一度に変えすぎず、似た内容同士で比較する。
- 外部リンクの配置やハッシュタグも、固定的なアルゴリズム攻略として扱わない。

## 5. Threads：ゲーム開発専用の運用

ユーザー決定により、Threadsはゲーム開発専用アカウントとして運用する。
現段階では『5分戦記』を中心に、制作過程と遊びの面白さを届ける。
既存アカウント[@oyamon_there2](https://www.threads.com/@oyamon_there2)を使用する。
2026-09-09時点で、ゲーム開発専用の表示名・自己紹介をブラウザで確認済み。
初回紹介投稿の公開・ピン留めはユーザーから実施報告あり。関連10アカウントのフォローを実施済み。
ゲーム開発専用という方針は、将来の他作品を扱わないという意味ではない。

### 発信する内容

- なぜこのゲームを作るのか、どんな遊びを実現したいのか。
- 操作を減らす設計、日本語の読みやすさ、地図の見せ方などの試行錯誤。
- 地図と「あなたならどう命令する？」、結果と作戦の振り返り。
- 実装後の実プレイ映像、試遊募集、更新情報。

一般的なAIニュースや受託開発の話はXに置く。
AI・コーディングの話も、ゲーム制作やプレイ体験との関係が伝わる場合はThreadsで扱う。
ゲーム開発者との制作交流と、ゲーマーとの遊びについての会話を両方育てる。

### プロフィール文の参考案（現在の設定内容とは別）

> 戦略ゲーム『5分戦記』を個人開発中。
> 操作は軽い。判断は重い。
> 地図と少数の指揮官で、敵の意図を読む。
> 制作過程・戦況・試遊情報を発信。初期版はオフライン・AI戦を予定。

### Xとの連携と工数

最初は週2投稿、返信・交流を含め週30〜45分を目安に、4〜6週間で振り返る。
地図・動画・開発メモはXと共有し、文章を読者向けに調整する。
Threadsだけを見ても理解できるようにし、毎回Xへ移動させない。
Xでは作り手の判断、Threadsではプレイ体験や制作の変化など、同じ素材の切り口を変える。

専用アカウントを始める際の紹介や試遊募集など、節目で両媒体を案内する。
両方のプロフィールから同じ公式サイト・試遊窓口へつなぎ、流入元を区別する。

## 6. SEO：少数のテーマに集中する

最初から「おすすめスマホゲーム」のような広い検索語を主戦場にしない。
以下は検索需要を確認する前の候補であり、検索数・上位表示を保証しない。

| 検索意図の候補 | 内容 |
| --- | --- |
| 5分戦記／5 MINUTE ORDERS | 公式情報、開発状況、配布先 |
| 同時ターン制とは | 小さな地図を使ったルール解説 |
| 戦略ゲームの読み合い | 陽動・防衛・敵の予測の具体例 |
| オフラインで遊べる戦略ゲーム | 初期版の対応内容と開発状況を正確に説明 |

SNSで反応のあった戦況を月1〜2本の解説記事にして素材を再利用する。
技術記事より、プレイヤーが面白いと感じる内容を販促上は優先する。
検索順位のための量産を避け、独自の戦況・判断・結果を説明する。

サイト公開後はSearch Consoleで表示された検索語とクリックを確認し、記事を調整する。
未配布の段階で遊べると誤認させる見出しや、未定の発売日を使わない。

## 7. 試遊・紹介・ストア

2国家で1試合を終えられ、対象端末で配布・動作を確認できたら小人数の試遊を募集する。
[ロードマップ](ROADMAP.md)のM2・M3の進捗に合わせ、90日という販促日程だけで公開を決めない。

試遊で確認すること:

- 説明なしで命令できるか。
- 相手の行動を読んだと感じるか。
- もう一度遊びたいか、実際に再プレイするか。

その後、戦略ゲームやボードゲームを扱う配信者・紹介者への個別紹介依頼を検討する。
登録者数より視聴者との相性を重視し、無償紹介の成立に発売計画を依存させない。

紹介用素材:

- 一文で分かる特徴。
- 短い実プレイ動画とスクリーンショット。
- 試遊方法、所要時間、公開・配信してよい範囲、問い合わせ先。

ストア公開時は説明文・画像を整え、掲載内容の比較検証は十分な流入が得られてから判断する。
配布OS、発売日、価格、登録窓口のサービスは本書では決定しない。

## 8. 最初の90日と工数

開始日から数える仮案。販促全体で週2〜3時間を上限の目安にする。
Xのゲーム関連週2投稿、Threadsの週2投稿、両媒体の交流、週15分の振り返りに、
記事・素材制作を含めて配分する。Threadsの週30〜45分もこの総枠に含む。
収まらない場合は交流日数や記事頻度を下げ、開発を圧迫しない。

| 期間 | 作業 | 判断 |
| --- | --- | --- |
| 1〜2週 | 紹介文、公式ページ、戦況投稿の型を用意 | 特徴が短く伝わるか |
| 3〜6週 | X・Threads各週2本のゲーム投稿、解説記事を月1〜2本の目安で運用 | どの戦況・訴求に反応するか |
| 7〜12週 | 好評な型を継続、配布可能なら試遊募集 | 興味がプレイにつながるか |

最初の4週間でXの投稿形式と対象層の相性を振り返る。
初期目標の仮置きは「試遊したい人を20人見つけ、配布可能になったら5〜10人に遊んでもらう」。
成果予測ではなく評価の目安であり、フォロワー数やインプレッションの保証目標は置かない。

## 9. 計測と改善

販促全体では、サイト訪問 → 試遊希望 → 実際の試遊 → 再プレイ希望・実施を見る。
投稿ごとに識別できるリンクと「どこで知ったか」の任意回答を利用する案とし、
ゲーム内の常時通信や必須アカウント登録は追加しない。

両媒体を合わせて週15分、投稿後48時間など同じ経過時間の数字を記録する。
媒体ごとに記録し、表示回数の定義や読者数が異なるため単純な優劣比較をしない。
Threadsは4〜6週間で、工数に対してゲームに関心のある人との会話・流入・試遊希望が増えたかを見る。

| 指標 | 確認すること |
| --- | --- |
| 投稿別インプレッション | 届いた題材・形式 |
| 返信・引用・リポストの内容 | 狙ったプレイヤーに響いているか |
| 週のフォロワー純増 | 続けて読みたいと思われたか |
| プロフィール訪問数（取得できる場合） | 投稿からゲームへの関心が生まれたか |
| サイト流入・試遊希望 | 販促につながったか |

インプレッションは人数ではない。フォロワー増加を特定の投稿だけの成果とは断定しない。
初週を基準に、投稿別インプレッションの中央値と週のフォロワー純増を比較する。
1本の大きな反応だけで成功とせず、複数投稿で再現を確認する。

| 観察 | 次の調整 |
| --- | --- |
| 表示は増えたがフォローされない | プロフィールと連載の魅力を見直す |
| 返信は少ないが試遊希望が増える | 販促として有効なので継続する |
| 開発者からだけ反応がある | 遊び手向けの戦況・体験を増やす |
| 1本だけ大きく伸びた | 次の数本で再現するか確かめる |

記録項目の例: 投稿日時、投稿URL、投稿の型、素材、比較条件、48時間後の表示・反応、
週初・週末のフォロワー数、サイト流入、試遊希望、学び、次の変更。
