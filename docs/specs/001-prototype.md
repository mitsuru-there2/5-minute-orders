# SPEC 001: 最初のプレイ可能な検証版

状態: 開発計画。原案由来の要件と、実装時に検証する仮案を分ける。本SPECの機能は未実装。
M1の詳細ルールは[SPEC 002](002-m1-rules.md)で検討中。未採用の候補を本SPECの確定要件と扱わない。

## 原案から採用する範囲

2国家、小規模マップ、指揮官1〜3人、軍団、移動・攻撃・防衛、不完全情報、同時ターン解決、簡単なAI。開始時の指揮官は1人。操作時間5分以内は設計目標であり、オフライン検証版で強制タイマーにはしない。

オンライン、通知、課金、外交、指揮官の物語的加入、複数速度、豪華な戦闘演出は初期版の対象外。最終的な指揮官5〜7人という原案は維持する。

## 確定した動作・保存方針

- 初期版はローカル動作のみ。進行、AI、命令確定、同時ターン解決を端末内で完結させる。
- 永続化には端末内のローカルDBのみを使う。外部サーバー、クラウドDB、別プロセスのDBサーバー、アカウント登録を必要としない。
- インストール後はネットワーク接続なしで新規ゲーム・プレイ・保存・再開を可能にする。開発ツールの取得とCIの通信はこの実行時要件の対象外。
- ローカルDBの製品と連携方式は保存機能実装前に選定する。現時点でDBは未実装。
- 保存とターン進行はapplicationの境界を通して利用し、domainとUIを具体的なDB・通信方式から独立させる。
- 将来のオンラインマルチプレイでは権威サーバーに進行を移せる設計とする。オンライン接続・同期・マッチングは初期版には実装しない。

## 実装に向けた仮案

- 6〜9領地の隣接グラフ。1指揮官につき1命令。未入力は防衛。
- 攻撃は敵領への移動として指定。移動不能・他国の指揮官・重複命令は確定前に拒否する。
- 全命令を固定した同一スナップショットから移動を計算し、戦闘、イベント、観測情報を順に生成する。
- 同一状態・命令・ルール版・seedは同一結果にする。システム時計・グローバル乱数に依存しない。
- 真のGameStateとプレイヤー別Observationを分離。UIとAIに敵の秘密命令や未観測軍勢を渡さない。単に画面で隠す実装は禁止。
- ローカルDBに保存するセーブはschema_version、rules_version、turn、seed、状態、確定命令を保持。描画ノードは保存しない。
- すれ違い移動、複数軍の合流、同着攻撃、退却先、首都陥落時の扱い、引き分け、勝利条件はプレイ版実装前に確定する。

## 検証すべきこと

- 戦況確認→入力→確定→結果→次ターンが最後まで動く。
- ネットワークを無効にした実機で、新規ゲームから保存・アプリ終了・再起動・再開まで完了する。
- 保存途中の中断でも不完全なターンを読み込まず、整合性のある確定済み状態から復帰できる。
- 命令の入力順で結果が変わらず、敵の非公開情報が漏れない。
- 7指揮官を想定した操作検証でも入力作業が5分以内。思考時間と操作時間を別に計測する。
- 「相手の行動を読んだ」判断と結果をプレイ記録に残し、単純な戦力差だけで勝敗が決まっていないか確認する。
- スマホ実機で文字、タップ、セーフエリア、中断・復帰を確認する。
