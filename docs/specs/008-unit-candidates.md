# SPEC 008: 名前付きユニットと毎ターンの募集候補

作成日: 2026-09-11 / 状態: **名前・個体差・毎ターンのランダム候補・地形発展による候補数変化を採用、詳細提案・未実装**。
関連: [兵種・購入](007-units-recruitment-garrisons.md) / [指揮官の成長](004-commanders.md) /
[領土開発](005-territory-development.md)

最新の解決順: [SPEC 009](009-turn-timing.md)の「Tの作業・徴兵完了→T+1開始時の戦闘」を採用。
本書の旧「戦闘後に開発・休養・指導者行動」「戦闘で作業取消」は同SPECに置き換える。
ターン境界の細部はSPEC 009で確認中。

## 1. 採用された方向

- ユニットは一人ずつ名前を持ち、パラメータにばらつきがある。
- 追加要望: C・B・A・S・SS等のランクで能力差を表示し、個体差は約100%まで許容する方向。
  100%は同兵種の最低と最高で約2倍という解釈で以下を提案する。厳密な基準・幅は未確定。
- 毎ターンランダムで登場するユニットから、購入・既存ユニットとの入れ替えを選ぶ。
- 地形と発展で募集の選択肢を変える。山は候補がほとんどおらず、発展した街では増える。
- 購入は即時確定し、そのターンから使える。指揮官不在の領土でも守備兵を購入できる。

以下の人数・範囲・費用・入れ替え後の兵の扱いは提案。
SPEC 007の同じ兵種を任意数量買える旧案を、人数限定の候補購入へ改訂する。
1ユニットは名前付きの兵士1人とし、複数兵士をまとめた匿名の部隊という旧表現を置き換える。
兵士個人に別々の命令は出さず、指揮官の軍団単位で操作する。守備隊は領土に留まり自動防衛する案。

## 2. 個体差の提案

全ユニットがID・名前・兵種を持つ。購入画面で現在HP／最大HP、攻撃、防御、特性、価格を示す案。
名前は識別用IDとは分け、同名でも同じ人物として扱わない。
兵種基準値を中心に個体差を作り、初回は最大HP・攻撃・防御の3項目に絞る。
移動距離・視界・命令回数は個体ごとに変えず、指揮官・派閥の既存能力と分離する。

- 旧±20%案を撤回し、同兵種の各基準能力に対して1.0〜2.0倍の幅を候補とする。
  ±100%（0〜2倍）という意味にはせず、0能力を通常生成しない。整数化は戦闘式と合わせて決める。
- 一部に強い精鋭候補を混ぜる案。最大HP・攻撃・防御を独立に無制限抽選せず、総合評価に上限を置く。
- 強い候補は高価格とし、強さと価格を同じ生成結果から算出する。具体的な評価式・精鋭率は未決定。
- 特性は0〜1個を候補とする。例: 森での戦闘が得意、山での防衛が得意、平地での突撃が得意。
  効果量と兵種・地形・指揮官・派閥能力との加算順は未決定。軍団全体への重複オーラは初回に加えない案。
- 能力値の2倍幅は許容するが、HP・攻撃・防御の組み合わせで実際の戦果は2倍を超え得る。
  実戦での強さが必ず2倍以内とは保証せず、人数・費用・兵種・地形込みで検証する。
- 個人のレベル・装備・忠誠・性格による命令拒否は追加しない案。指揮官の育成と分ける。

選択回答1A・2B・3Aを採用: 入れ替えた兵士は解雇し、控え枠・返金なし。
HP0の兵士は負傷離脱し、一定ターン後に復帰する。生存兵は指揮官の休養命令で軍団全体を回復する。
選択回答6A・7A・8A・9A・10Bを採用:
- 負傷中も指揮枠を使う。復帰を待つか、解雇して新兵を迎える。
- 2ターン休んで元の軍団・守備隊へ自動復帰する。
- 指揮官の休養は自領限定。移動せず、軍団全体の生存兵を回復する。
- 守備隊の生存兵は戦闘の有無にかかわらず20%自然回復する（37Aで条件更新）。

選択回答11A・12A・13A・14A・15Aを採用:

- Tの戦闘で離脱した兵はT+1・T+2を休み、T+3開始時の戦闘前に全回復して復帰する（35Aで時点更新）。
- 軍団の休養は全生存兵を全回復。その他はターン末に自領にいる軍団のみ最大HPの20%自然回復（36B）。守備隊も20%回復（37A）。
  失ったHPに対する割合ではない。最大HPを超えない。
- T開始時に戦闘した軍団も自領で休養でき、T+1戦闘前に回復が完了する（34A・SPEC 009）。
- 元の軍団・守備隊が消滅した負傷兵は離脱し、復帰しない。首都や他軍への自動移管はしない。
  所属の消滅を何で判定するか（全員負傷と指揮官喪失の区別等）は戦闘契約で具体化する。
- 国家脱落では療養中も含めて全兵を除去し、復帰させない。

軍団の休養・守備隊の自動回復は資金不要（19A採用）。端数、通常回復の解決時点は未決定。
端数は切り上げ、通常回復は戦闘・脱落判定後に適用する案。負傷者を通常回復で早期復帰させない。
療養は解雇後の控えとは区別し、解雇者を自動復帰させない。指揮官自身の敗北処理は別途決める。
旧「部隊の欠員補充」は生存者の治療と新しい人物の採用に分け直す必要がある。
風原連邦の行軍補給も、個人HPの回復とするかを再検討し、未承認の回復規則を実装しない。

### ランク表示の具体案

ランクはC < B < A < S < SS。候補一覧は名前・兵種・総合ランク・特性・価格を表示し、
詳細では最大HP・攻撃・防御それぞれのランクと実数を確認できる案。
現在HPは正確な数値を常に示し、負傷をランクで隠さない。総合ランクは負傷で変えない。

| ランク | 同兵種の基準能力を100とした範囲案 |
| --- | --- |
| C | 100以上120未満 |
| B | 120以上140未満 |
| A | 140以上160未満 |
| S | 160以上180未満 |
| SS | 180〜200 |

まず実能力値を生成し、その値を兵種基準で正規化して能力別ランクを求める案。
総合ランクは最大HP・攻撃・防御の正規化値の平均から同じ表で求める仮案。
ランク倍率をさらに能力値へ掛けず、二重強化しない。特性は総合ランクから分けて表示し、価格評価で考慮する案。
攻撃S・防御B・HP Aの人物も存在し、全項目が必ず同ランクにはならない。
兵種ごとに基準が違うため、総合Aの歩兵と総合Aの騎兵が同じ戦闘能力であるとは意味しない。
総合ランクは人物比較の目安であり、敵との相性・地形込みの勝率予測ではない。

出現率は未決定。C・Bが中心、Aは時々、S・SSは稀となる生成分布を候補とし、
範囲全体から均等抽選して上位ランクが大量に出る方式にはしない案。
SSだけを待つことや頻繁な全員交換が最善にならないよう、価格・候補数・試合長を合わせて調整する。
ランク閾値・端数処理・総合評価式はルール版に固定し、表示と購入価格で異なる能力を参照しない。

## 3. 地形・発展と候補数の提案

領土ごとにそのターン限定の募集候補一覧を持つ。同じ土地の複数指揮官と守備隊は同じ一覧を使う。
全自領を毎回開かず比較できる一覧をUIへ設ける案。候補は配属先がある現地でのみ購入できる。

| 地形 | Lv1（初期） | Lv2 | Lv3 |
| --- | --- | --- | --- |
| 平地 | 3人 | 4人 | 5人 |
| 森 | 2人 | 3人 | 4人 |
| 山 | 0〜1人 | 1人 | 2人 |
| 水 | 0人 | 対象外 | 対象外 |

24A・26Aにより上記の3段階表を採用。水は募集0人とし、発展段階の対象外とする案。
山の0〜1人は50%で1人（24A採用）。水の開発不可は別途確認する。
発展した平地を「街」と呼び、新たな地形・街Lvは作らない案。
首都は最低2候補を保証する（25A採用）。首都が山でも地形表より優先する。
購入費用は別途必要であり、候補保証は無料兵の保証ではない。

歩兵・弓兵・騎兵を共通候補とし、当面は地形で人数だけを変える案。
兵種の出現率まで地形で偏らせること、街で精鋭率も上げることは追加しない。
候補数増加自体が良い人物に出会う確率を上げるため、質の上昇も同時に重ねない。
守備隊の歩兵限定は17Aで採用済み。候補が1人以上なら最低1人の歩兵を保証する（25A採用）。
全兵種が毎ターン必ず揃う保証はしない。

## 4. 候補更新・購入・入れ替え

各ターン開始に、その時点の地形・発展・所有状態から候補を一度生成する案。
未購入候補は次ターンに退出し、購入済みの人物は同じ名前・能力で軍団または守備隊に残る。
購入しても同ターン中の候補枠は補充せず、有料リロール・候補の翌ターン取り置きは設けない案。
候補なし・希望兵種なしの土地では購入できない。資金と枠があっても候補数を超えて買えない。

- 候補はIDで指定し、現在の所有・現地配属・資金・指揮上限・候補の未購入状態を検証する。
- 現地にいる自軍指揮官の軍団、または指揮官不要の当該土地の守備隊へ配属する。
  画面を全国一覧にしても遠隔の軍団へ即時配送はしない。
- 購入・入れ替えは指揮官の行動を消費せず、その後に進軍・防衛・開発等を選べる（20A採用）。
- 同じ候補を軍団と守備隊の両方へ買えない。複数の指揮官にも複製しない。
- 空き枠があれば追加、満員なら置き換え対象を選べる。最大枠に達する前の任意の入れ替えも可能な案。
- 入れ替え前に、新旧の名前・能力差・費用・外れる人物の扱いを表示する。
- 外した人物は解雇し、控え枠・返金なし（採用済み）。募集一覧へ戻さない案。
  負傷中の人物も解雇して新兵を迎えられる（6A採用）。解雇した人物は復帰しない。
- 購入／入れ替えは候補消費・支払い・旧人物の処理・新人物の配属を一括で確定する。
  検証失敗時はすべて変更しない。先に旧人物だけを解雇してから購入に失敗する状態を作らない。
- 確定後の取消なし、当ターン利用可、命令確定後の購入不可というSPEC 007の採用事項・提案を引き継ぐ。

占領はターン解決時に発生するため、新領土では次の入力開始時に新所有国向けの候補を生成する案。
同ターン中の旧所有国の募集残りを戦利品として引き継がない。開発による候補増加も翌ターンから。
脱落国の購入兵は既存ルールで除去し、未購入候補は戦闘員・国家資産として数えない。

## 5. 決定性・観測・入力負担

49B・50A・51A: 土地の所有者は視界内だけ更新。通常観測は敵指揮官の存在と兵数の概数とし、
敵の名前付き兵士の能力・編成は偵察で確認する。指揮官・守備隊・首都が現在地と上下左右へ視界を出す。
通常観測へ敵の詳細候補や兵士IDを混ぜない。自領は全マス常時視界内、山の通常視界は距離2、
敵兵数は規模表示、偵察は距離3以内の1マスの詳細を確認（52追加回答・53A〜55A）。
規模の閾値・負傷者の数え方、喪失時の敵情報ログは未決定。

候補生成は試合seed・ルール版・ターン・領土ID・候補枠を基に行い、別用途の乱数と分離する案。
候補の名前・兵種・数値・特性・価格・購入済み状態を保存対象とし、ロードや画面再表示で再抽選しない。
同じ条件なら地図の走査順や購入操作の順番で他領土の候補が変わらないようにする。
自国の現在の候補だけをObservationへ渡す案。敵の候補・購入時刻・購入内容は入力中に公開しない。
AIも同じ候補と観測情報を使い、候補生成seedから敵情報を推測する実装にしない。

最大50／60人の個別比較が負担になるため、通常画面では兵種別の人数と軍団の要約を表示する案。
採用時だけ候補カードと入れ替え対象を比較し、能力差と費用を一画面に収める。
「採用可能な候補のみ」「空き枠のある軍団」等で絞り込み、候補閲覧や毎ターンの入れ替えを必須にしない。
上位互換が頻繁に出て全員の交換が定石にならないか、候補数・価格差・精鋭率を試遊で検証する。

必要な検証: ランク境界・兵種別正規化・二重倍率なし・負傷時の表示、候補数と首都例外、所有・配属制限、重複購入拒否、原子的入れ替え、ロード時固定、
指揮上限と守備隊上限、開発後の次ターン候補増加、敵の候補の秘匿、5分以内の編成判断。
数値・候補生成・戦闘・セーブは未実装であり、文書化をバランス検証済みと扱わない。
